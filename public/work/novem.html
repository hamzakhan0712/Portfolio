The problem

Small store owners sit in an awkward gap. The analytics built into Shopify or WooCommerce stop at "revenue went down". Enterprise BI is priced for teams that already have an analyst, and open-source data tools assume you can write SQL and run a warehouse.

So decisions about stock, pricing and ad spend get made from a spreadsheet export and a hunch. NOVEM is aimed at that gap.

What I built

A Python engine that does the data work, wrapped in a desktop app so a store owner can install it like any other program.

  • Customers: RFM segments, churn risk and lifetime value, cohort retention.
  • Products: revenue breakdowns, market-basket rules and stock-out analysis.
  • Insights: findings ranked by impact, anomaly detection and a revenue breakdown that explains why a number moved.
  • Forecasts for revenue, orders, customers and order value, and a reports builder with PDF output.
  • About 170 endpoints across 23 FastAPI routers
  • Five import sources, one pipeline
  • Ships as a single Windows installer

Backend decisions

Two databases, split by workload
Analytical tables such as orders, customers, products and ad spend live in DuckDB, which is built for scans and aggregations. Everything transactional, such as settings, import history and lineage, sessions and encrypted connector credentials, lives in SQLite. All analytical rows are scoped by store_id, so several stores stay isolated in one install.
The engine is a managed local service
In development, uvicorn and Vite run side by side. In a release, the engine is frozen with PyInstaller and shipped inside the installer. The Tauri shell starts it as a child process, waits for its port to accept connections, and asks it to shut down cleanly on exit.
Privacy by default on import
Every source goes through the same steps: parse, detect the schema, map columns, clean and normalise channels, mask PII, score quality, then merge. Customer emails and names are SHA-256 hashed on import, so the raw values are never stored.
Models with fallbacks
Lifetime value uses BG/NBD and Gamma-Gamma through lifetimes, baskets use Apriori, and anomalies use z-scores. Forecasts use Prophet and fall back to a linear trend when Prophet is not available, so a missing dependency degrades the feature instead of breaking the endpoint.
An assistant that works offline
Questions are answered with retrieval over a cached summary of the store's own data, using a local Ollama model. When Ollama is not running, the engine falls back to rule-based answers instead of an error.
Quality gates in CI
CI runs Ruff and pytest on the engine, and ESLint and Vitest on the interface.
