How I build backends

The habits that show up in every project above.

Model the business before the screens
The co-living platform rents beds, so the bed carries the rent, deposit and status. Getting that unit right first kept every later feature simple.
Make bad states hard to save
Unique constraints, checks before writes and transaction.atomic blocks, so the app refuses a second active contract on the same bed.
Scope data where it is queried
Access rules live in querysets and permission checks, not in templates, so every new view starts from the same rules.
Automate the routine work
Recurring rent, reminders and status updates run as management commands with dry-run flags, so they can be tested before they touch real data.
