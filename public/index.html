How I work

Habits that keep software running.

Clients don't see the code. They see whether it works on Monday morning, so these are habits, not extras.

01

Own it end to end

I scope the work with the client, design the data model, build it, deploy it and support it afterwards, so nothing falls between people.

02

Test and automate

Playwright for the screens people use, pytest for the logic, and CI pipelines that run linters and tests automatically.

03

Ship in versions

Semantic versioning, a written changelog and auto-updating installers, so every release is traceable and easy to roll out.

04

Write decisions down

My recent projects keep a decision log: what was chosen, why, and how to reverse it. The next engineer, or me in six months, isn't left guessing.
